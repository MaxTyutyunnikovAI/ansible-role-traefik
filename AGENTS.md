# AGENTS.md — руководство для AI-агентов

Этот файл описывает правила и контекст работы с репозиторием роли Ansible `w0.traefik`
(установка Traefik v3 как systemd-сервиса).

## О проекте
- **Тип**: роль Ansible Galaxy (namespace `w0`, имя `traefik`).
- **Назначение**: декларативная установка и настройка Traefik v3 на Linux-хостах с systemd.
- **Лицензия**: Apache-2.0.
- **Язык документации**: русский (README.md, CHANGELOG.md, TODO.md, THINKING.md, комментарии в коде допускается оставлять на английском, если они уже существуют).

## Структура репозитория
```
defaults/main.yml   # все настраиваемые переменные (единственный источник правды по default-значениям)
vars/main.yml       # внутренние переменные (карта архитектур go_arch_map)
tasks/              # main.yml последовательно включает install → configure → systemd → logrotate
handlers/main.yml   # цепочка validate_and_restart_traefik + reload systemd
templates/          # traefik.yml.j2, traefik.service.j2, traefik-logrotate.j2
meta/main.yml       # метаданные Galaxy
molecule/default/   # тестовый сценарий (docker, RockyLinux 9)
tests/              # минимальный smoke-плейбук
.github/workflows/  # публикация роли на Galaxy по тегу
```

## Правила внесения изменений
1. **Не ломайте контракт переменных**: имена префикса `traefik_*` стабильны; любое изменение
   дефолтов — только через `defaults/main.yml` и с записью в `CHANGELOG.md`.
2. **Идемпотентность обязательна**: новые задачи должны корректно работать в `--check`-режиме
   (`check_mode: false` там, где задача должна выполняться реально) и не «changed» без причины
   (`changed_when`).
3. **Никогда не перезапускайте сервис напрямую**. Все изменения конфигурации/юнита/бинарника
   должны использовать `notify: validate_and_restart_traefik` — перезапуск допускается только
   после успешного тайм-аутного пробного запуска новой конфигурации с откатом на
   `<конфиг>.bak` при провале (см. `handlers/main.yml`; офлайн-режима `--check` в Traefik v3
   не существует — обоснование в `THINKING.md`, раздел 2).
4. **Безопасность по умолчанию**: сохраняйте закалку systemd-юнита и ограничительные режимы
   файлов (`0640`/`0750`); не добавляйте `privileged`-режимы без явной необходимости и комментария.
5. **Модульность задач**: новая логика добавляется в соответствующий модуль `tasks/*.yml`,
   а не в `main.yml`; каждый модуль самодостаточен и тестируем.
6. **Полностью квалифицированные имена модулей** (`ansible.builtin.*`) — стиль, принятый в роли.
7. Комментарии в YAML/Jinja2 должны объяснять **«почему»**, а не «что» (см. примечания про
   `--check`, сокеты entry points, SIGUSR1).

## Стиль кода
- Имена задач: с заглавной буквы, повелительное наклонение («Create ...», «Deploy ...»).
- Отступы: 2 пробела; строки YAML с шаблонами Jinja2 — в двойных кавычках.
- Шаблоны `.j2` начинаются с Jinja-комментария `{#- ... -#}` с описанием назначения.

## Тестирование
- Перед коммитом: `ansible-lint`, `yamllint`, `molecule test` (нужен docker).
- Быстрая проверка синтаксиса: `ansible-playbook --syntax-check tests/test.yml`.
- Новые фичи сопровождаются тестами в molecule (converge + idempotence уже покрыты сценарием).

## Коммиты и история
- Изменения, видимые пользователю, фиксируются в `CHANGELOG.md` (секция «Не выпущено»).
- При изменении планов/долгосрочных задач обновляйте `TODO.md`.
- Решения и обоснования архитектуры документируются в `THINKING.md`.

## Чего избегать
- Удаления или переименования переменных без записи в CHANGELOG и периода совместимости.
- Инлайн-`validate:` для шаблона `traefik.yml.j2` (конфликтует с занятыми сокетами запущенного Traefik).
- `copytruncate` в logrotate (потеря строк) — используйте механизм SIGUSR1.
- Предположений об ОС без systemd: роль содержит `assert` — новые фичи должны учитывать это.
